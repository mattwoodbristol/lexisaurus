# Course packs

A course pack is a folder of plain files that defines one language's course: the lessons in
order, the lessons planned but not yet written, and the conversation topics. Edit it in any
editor (or ask Claude Code to), check it, then sync it into the app. Progress is kept.

```
<pack>/
  course.json          title, lesson order, planned lessons
  lessons/<id>.md      one file per lesson
  topics.json          conversation topics (optional)
```

**Without a terminal:** Settings → Course in the app downloads the course as a zip of these
files and uploads changed ones (the whole zip, or just the lesson files that changed). It runs
the same checks and shows what will change before saving. A lesson file uploaded on its own
replaces the lesson with its id, or is added at the end of the course. "Plan the next lessons
with Claude" on the same page writes the `planned` list from your goals.

`examples/course-zh/` is a small complete example. Your own course lives in
`data/courses/<lang>/`, which git ignores. Run `git init` inside it if you want its history.

## Commands

```sh
npm run course -- check  data/courses/zh                     # validate, offline
npm run course -- sync   data/courses/zh --local --dry-run   # show what would change
npm run course -- sync   data/courses/zh --local             # apply to the local database
npm run course -- sync   data/courses/zh --remote            # apply to the live app
npm run course -- export data/courses/zh --remote            # write the live course out as a pack
npm run course -- export data/courses/zh --remote --new      # pull generated lessons into the pack
```

Always dry-run against `--remote` first. The SQL it would run is saved next to the pack.

## course.json

```json
{
  "lang": "zh",
  "title": "Mandarin",
  "lessons": ["time-place-word-order", "measure-words", "comparisons"],
  "planned": [
    { "id": "duration-and-frequency", "title": "Duration and frequency", "level": "HSK 3-4",
      "focus": "What the lesson should teach. Claude writes the lesson from this." }
  ]
}
```

- **Order is the course.** Lesson numbers come from the position in `lessons`. Move an id to
  reorder; titles are renumbered on sync.
- **Ids are permanent.** Completion, grammar review cards and history are keyed on the id. Rename
  the title freely, never the id. Ids are lower-case letters, digits and hyphens, and the lesson
  file must be `lessons/<id>.md`.
- **Planned lessons** are generated by the app ("Generate next lesson") in order. The generated
  lesson keeps the planned id, and `export --new` moves it from `planned` into `lessons`.

## Lesson files

```markdown
---
id: comparisons
level: HSK 3
---
# 比 — Comparisons

**Pattern:** A 比 B + adjective

## Grammar

Explanation paragraphs, separated by blank lines.

### Examples

- 今天比昨天冷。 — Today is colder than yesterday.

### Key points

- No word for 'more' needed

## Drills

1. Bristol is bigger than Nottingham. → 布里斯托比诺丁汉大。

## Common errors

- ✗ 比英文没不同 → ✓ 跟英文没什么不同 — use 跟 not 比 for similarity

## Grammar points

- **比**: A 比 B + adjective

## Conversation

Suggested prompt for the practice chat.
```

Rules the checker enforces:

- At least 2 examples, 3 drills and 1 grammar point.
- Chinese fields are Hanzi only: never write pinyin, the app adds it.
- Examples use ` — ` between Chinese and English. Drills use ` → ` between English and Chinese.
  Common errors are `✗ wrong → ✓ right`, with an optional ` — note`.
- Grammar point titles are unique within a lesson.

Drills become review sentences for the lesson's first grammar point. Grammar points enter spaced
repetition when the lesson is marked done.

## Practice sections (stepped lessons)

A lesson with both of these sections runs as steps: warm-up (recall from earlier lessons),
learn, recognise, build (word tiles from the first drills), produce (typed, marked by Claude
when not an exact match), fix (the common errors), use it (a guided chat) and a scored lesson
check. Passing the check (setting `lesson.pass_mark`, default 80%) marks the lesson done; below
it, the lesson's grammar comes back in reviews the next day.

```markdown
## Recognise

- Today is colder than yesterday.
  - 今天比昨天冷。 ✓
  - 今天比昨天很冷。
  - 今天冷比昨天。

## Lesson check

- Summer is hotter than spring.
  - 夏天比春天热。 ✓
  - 夏天比春天很热。
- My mother is busier than my father. → 我妈妈比我爸爸忙。
- ✗ 他比我很高。 → ✓ 他比我高。 — no 很 in a 比 sentence
```

In the check, an item with indented options is multiple choice (one option marked ✓),
`English → Chinese` is typed, and `✗ wrong → ✓ right` is a mistake to fix. Aim for 8 drills,
4 recognise questions and 8 check items (3 choice, 3 typed, 2 fixes). Draft them for lessons
that lack them with:

```sh
npm run course -- practice data/courses/zh [--lesson <id>] [--force]
```

In the app, any marked answer has a "Query this mark" link: Sonnet re-checks it, flips the mark
if the learner was right (rescoring a lesson check), and logs answer keys it finds wrong. List
those to fix in the lesson files:

```sh
npm run course -- queries --remote
```

## What sync does

- Lessons are matched by id. The first sync gives the lessons imported before packs existed
  their ids, matching by course number.
- A matched lesson keeps its database row, so it stays done, and its grammar cards keep their
  history. Grammar points are matched by title, then by position, so a renamed one keeps its card.
- Drills and common errors are replaced by the pack's: stale ones are removed. Mistakes recorded
  in conversations are never touched.
- Lessons generated in the app but not yet in the pack stay, numbered after the pack's lessons.
- A lesson removed from the pack is kept and reported, unless you pass `--prune`. Pruning
  deletes it with its grammar cards.
- With a `topics.json`, topics are replaced by it (topic history is kept for the ones that
  stay). Without one, topics are left alone.
